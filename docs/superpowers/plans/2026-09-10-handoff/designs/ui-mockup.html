Proposal 1

An activity panel on every answer

Each answer gets one collapsible panel above it. Collapsed, it is a single summary line. One click shows the steps in plain language — the searches, the files opened, and the model's thinking when the model shares it. A sidebar switch adds the raw tool arguments, what the scope pin changed, and a result preview. The model's reasoning is shown only when the endpoint actually returns it, and the page says honestly when it doesn't.

Proposal 2

Model parameters in the Connection dialog

After you pick a model, the dialog shows seven settings — reasoning effort, temperature, top p, max tokens, seed, and the two penalties — enabled only when the model supports them. Support comes from the endpoint's own model listing (OpenRouter reports it per model), then a small model-family table, and otherwise the rows stay editable but marked unverified. A blank field means “use the provider's default” and is never sent. The same seven keys live in YAML under ask_your_docs.llm.params; the dialog overrides them for your session only.

Decisions before I build it

Everything else in both designs follows the existing rules (YAML-only settings, frozen MCP tools, sealed eval runs). Reply with the IDs you disagree with; silence on an item means the recommendation.

Activity panel

A1Keep failed and stopped turns in the chat history, with their steps?Yes — today they vanish on the next rerun, which hides where things broke.
A2Token counts: turn on stream_usage (changes the request) or show counts only when the provider sends them?Only when sent. OpenRouter sends them already, so nothing changes on the wire.
A3Stream the steps live but show the answer text only when it's complete?Yes for v1. Streaming the answer flickers, because text before a tool call is narration, not the answer.
A4Cap langchain-openai below 2.0? Capturing reasoning overrides two of its private methods.Yes, plus a contract test that fails CI if the methods change. If capture ever breaks, the badge says “unknown” and chat keeps working.

Model parameters

P1Ship all seven settings, including the two penalties?Seven — the penalties are first-class client fields and about 240 OpenRouter models list them.
P2Later phase: typed settings that go in the request body — thinking on/off, top_k, min_p, repetition penalty. This departs from the LLM-connection decision O2.Ratify it as a separate change; phase 1 ships without it.
P3The question-rewrite step: pin temperature to 0 when a temperature is set, and inherit the effort?Yes — deterministic rewrites, and eval runs stay a pure function of their YAML.
P4Eval runs: accept parameters only from the run's own YAML and refuse ones coming from config files or env vars?Refuse — no identity hashes move, and a shell export can't change what a run measures.
P5Raise the langchain-openai floor to the first release with a typed reasoning_effort?Yes (today it is >=0.2).
P6A tiny paid check (under $0.001) that max_completion_tokens works on OpenRouter and a local server?Yes, before release.

Proposed to ship together in one UI release with the two items already approved: one search server per chat page instead of one per tool call, and the Streamlit file watcher off by default.
