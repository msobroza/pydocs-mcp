❓ **Q19 — #394: count the zero hits at $0 first, and close without a paid arm if there are too few?**

Finding. The zero-hit Pointer now renders on very few responses, and even before that the effect was too small to see.
- Since ADR 0027 (merged 2026-11-08, default on) a `kind="api"` zero hit is answered in the same response with the `kind="any"` rows; the overview Pointer renders only when that fallback is empty too (`docs/adr/0027-…:113-119`; `api_zero_hit_fallback.py:152-160`). The issue was written before this.
- The only recorded zero-hit counts are API zero hits: 17 over 60 RepoQA tasks in the 2026-11-08 three-seed run of the pre-change main (`docs/adr/0027-…:36-42`). None of the sources I read records a default-kind zero hit. The eval's serving pipeline is dense top-k with no score floor in its YAML (`benchmarks/configs/pipelines/exp_dense.yaml`), so an unfiltered default-kind search returns rows whenever the slice is non-empty (inferred from the YAML; step defaults not traced).
- Arithmetic: the Pointer costs at most one Turn per zero hit. With the old rate (≤17 of 60 tasks) the largest possible effect on the mean is about 0.28 Turns; the A/A edge at n=20 is about ±0.6 Turns (`366-comments.md` comment 6). After ADR 0027 the rate is lower. Under Q10's point-estimate rule, three arms that differ on one or two tasks produce a PASS or FAIL that is run-to-run noise.

Options:
1. **Count first, with a floor fixed in advance.** A $0 read of the stored arm traces: tasks with at least one zero-hit search, what the next call was, whether the Needle was reached afterwards. The floor: (share of tasks with a zero hit) × 1 Turn must reach the slice's A/A edge — 12 of 20 tasks on `small_dev`, about 27 of 100 on `repoqa-qa/dev`. Below it, #394 closes unmerged with the count table in #366 and no paid arm, which also clears its edge on #396. Above it, the arms are settled in the next round (Q20).
2. **Close now**, on the argument alone. Fastest; leaves no number on record.
3. **Build a zero-hit-enriched probe set** and run the arms there, informational. A zero hit can only be forced through filters (`package=`, `scope=`, a decision search with no records), so the set measures a contrived population; it needs authoring and its own baseline.
4. **Run as written on `small_dev`.** About $0.25–0.40 at the recorded prices ($0.08–0.13 per 20-task arm) for a verdict that cannot be told from noise.

➡️ Recommended: option 1 — count first with the floor above; I expect it to end in a close-unmerged with the table recorded.
